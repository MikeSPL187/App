# Тихие файлы 1.2 — что сделано

Версия 1.2 добавляет к [версии 1.1](v1.1.md) работу с серверами в локальной сети (F16) и «Доступ с ПК» (F17). Работа шла по [техническому заданию](../spec/TZ.md) и [макетам](../design/mockups) 08 и 09.

| | |
|---|---|
| Новые модули | `core/security` (Keystore, проверка сертификатов), `core/network` (протоколы, сессии, FTP-сервер), `feature/network` (раздел «Сеть») |
| Новые библиотеки | sshj 0.41.2 (SFTP), smbj 0.15.0 (SMB 2/3), commons-net 3.13.0 (FTP/FTPS), BouncyCastle 1.86 (алгоритмы SSH и SMB, сертификат сервера), ZXing core 3.5.3 (QR-код). WebDAV — собственный клиент HTTP/1.1 |
| Размер release APK | ≈ 9,1 МБ (было 7,0 МБ; почти всё прибавили BouncyCastle и SSH) |
| Новые разрешения | `INTERNET`, `ACCESS_NETWORK_STATE`, `ACCESS_WIFI_STATE` — без запроса (раздел 7). Интернет нужен только для серверов, которые пользователь добавил сам, и для «Доступа с ПК»; аналитики и рекламы по-прежнему нет |
| База данных | `quietfiles.db` версии 4: таблица `connections` без секретов (автомиграция 3 → 4, проверена тестом) |
| Тесты | 50+ новых тестов, протоколы проверяются против настоящих серверов: Apache MINA SSHD (SFTP), Apache FtpServer (FTP, FTPS явный и неявный), собственный тестовый сервер WebDAV на сокетах (HTTP и HTTPS) |

Сборка и проверка — как раньше:

```bash
echo "sdk.dir=$ANDROID_HOME" > local.properties
./gradlew --no-parallel test lintDebug :app:assembleRelease
```

### Как устроено

- **Пути.** Файл на сервере внутри приложения — обычный путь `/qf-net/<id подключения>/<путь на сервере>` (`NetworkPaths`). Поэтому родитель, имя, хлебные крошки, избранное, окна и очередь операций работают с серверами без отдельного кода. `RoutingStorageProvider` отправляет такие пути в `NetworkStorageProvider`, остальные — в файлы устройства.
- **Сессии.** `RemoteSessions` открывает сессию при первом обращении, один раз переподключается при обрыве, закрывает сессию через 5 минут без дела (если не идёт чтение или запись) и публикует статусы для списка.
- **SMB.** Корень подключения без указанного ресурса — список общих ресурсов. smbj его не умеет, поэтому вызов NetrShareEnum службы SRVSVC по DCE/RPC сделан своим кодом (`SrvSvc`, около 200 строк вместо библиотеки DCE/RPC с Guava на несколько мегабайт).
- **WebDAV.** Свой небольшой клиент HTTP/1.1 (keep-alive, chunked, Range, Basic и Digest). Системный `HttpURLConnection` не умеет методы WebDAV, а OkHttp на Android подчиняется общему запрету открытого HTTP из Network Security Config. Нам же HTTP нужен ровно для одного сервера, который пользователь явно добавил «без шифрования».

## Отличия от ТЗ и макетов

- **SMB1.** Используемая библиотека SMB1 не поддерживает. Сервер, который говорит только на SMB1, получает понятное сообщение: «включите на сервере SMB2 или SMB3». Переключателя «разрешить SMB1» в форме нет.
- **Облака в макете 08.** Блок «Облака» относится к 2.0 (F18), в 1.2 его нет. Раздел называется «Сеть».
- **S8 и локальный прокси.** Вместо HTTP-прокси на 127.0.0.1 видео и музыка читаются собственным источником данных Media3 прямо из `StorageProvider`. Это безопаснее: нет открытого порта и токена, которые нужно защищать. Требование S8 «прокси живёт, пока идёт воспроизведение» тем самым не нужно.
- **F16.7 докачка.** Копирование с сервера при обрыве не продолжается с места: операция завершается ошибкой, временный `.qfpart` удаляется, и её можно повторить. Чтение с середины файла поддерживают все протоколы, для видео это и есть «докачка» при перемотке и переподключении.
- **Открытие файлов с сервера.** Видео и музыка играют потоком. Остальные файлы (фото, тексты, PDF) скачиваются во временную папку с прогрессом и кнопкой «Отмена» и открываются копией только для чтения: изменения на сервер не возвращаются. Чтобы отредактировать файл, его копируют на телефон. Фото открывается без перелистывания соседних.
- **Миниатюры на сервере** не строятся: каждая означала бы загрузку файла по сети. Вместо них значки типов.
- **Теги музыки с сервера** читаются через `MediaDataSource` по сети; обложка из `cover.jpg` в папке сервера не ищется.
- **Модули.** В ТЗ протоколы разнесены по `:provider:smb`, `:provider:sftp` и т. д. Здесь они лежат пакетами одного модуля `core/network`: у них общие сессии, ошибки и проверка TLS, а отдельные модули только удлинили бы сборку.
- **«Доступ с ПК»: вход.** Логин — `phone`. QR-код содержит адрес и логин, но не пароль, чтобы его нельзя было подсмотреть с экрана. Сервер отдаёт основное хранилище (`/storage/emulated/0`); SD-карта через сервер пока недоступна.
- **FTPS сервера и сессии TLS.** Сервер не требует от клиента повторно использовать сессию TLS на канале данных (так делает строгий режим vsftpd). Это проще для клиентов, но немного слабее защищает от подмены канала данных; канал данных при этом принимается только с того же адреса, что и управляющий.
- **Тип службы.** Служба «Доступа с ПК» — `dataSync`, как у очереди операций. Ограничение Android 15 в 6 часов не мешает: сервер и так останавливается через 30 минут простоя.

## Что проверено и что нет

- Юнит-тесты против настоящих серверов:
  - SFTP: TOFU (незнакомый и изменившийся ключ), неверный пароль, файлы туда и обратно, чтение со смещения, ключ ED25519 с парольной фразой и неверная фраза.
  - FTP и FTPS: закрепление самоподписанного сертификата и блокировка при его смене, неявный TLS.
  - WebDAV: HTTP и HTTPS с закреплением, кириллица и пробелы в путях, chunked-ответы, Range, квоты, разбор ответов Nextcloud.
  - Хранилище целиком: маршрутизация путей, перенос внутри сервера, переподключение после обрыва, нет секретов → «войдите снова».
  - Сервер «Доступа с ПК»: наш клиент через FTPS, отказ во входе без TLS, выход за корень через `..`, анонимный доступ только на чтение, отключение клиента.
  - Разбор SRVSVC, NBSTAT и ключей SSH; шифрованное хранилище секретов, в том числе потеря ключа и ошибка шифрования.
- `AppSmokeTest` проходит новые сценарии на настоящем SFTP-сервере в той же машине и сохраняет снимки:
  - пустой раздел «Сеть», форма подключения, отпечаток ключа, папка сервера, файл с сервера в редакторе, список со статусом «В сети» (52–57);
  - «Доступ с ПК» без Wi-Fi, работающий сервер, подробности с QR-кодом и подключённым компьютером (58–60).
- lint без ошибок и предупреждений, release-сборка с R8 проходит.
- **Не проверено на устройстве** (эмулятора и серверов в среде нет):
  - настоящие SMB-серверы: Windows, Samba, NAS (на них список ресурсов SRVSVC проверен только разбором собранных по спецификации пакетов);
  - Nextcloud и другие серверы WebDAV в сети;
  - поиск mDNS и NetBIOS;
  - Android Keystore на реальном железе;
  - «Доступ с ПК» с FileZilla, WinSCP и проводником Windows по Wi-Fi и через точку доступа;
  - работа R8-сборки с BouncyCastle: правила сохраняют только нужные алгоритмы, это стоит проверить подключением по SFTP и SMB из release-сборки.

  Нужен прогон по разделу 12 ТЗ.
