## 2. Карта функций

**Локальные файлы.** Просмотр, копирование, перемещение, переименование, групповое переименование с нумерацией, сжатие и распаковка (zip, 7z, rar, tar, gz, bz2, xz; есть редактирование архива на месте), контрольные суммы, свойства, скрытие файлов, закладки, история, ярлыки на рабочий стол, «открытые окна» (несколько вкладок), корзина.

**Библиотека.** Фото, видео, аудио, документы, архивы, APK, загрузки, новые файлы, недавние, избранное.

**Анализ памяти.** Большие файлы и папки, дубликаты (в том числе в загрузках), кэш приложений, неиспользуемые приложения (через `PACKAGE_USAGE_STATS`).

**Приложения.** Список, резервная копия APK, удаление, установщик Split APK (собственный формат `.apk+` / `application/x-splitapk`).

**Встроенные просмотрщики.** Изображения (слайд-шоу, EXIF, обои), видео на Media3 (субтитры, скорость, жесты), музыкальный плеер на базе UAMP (`com.example.android.uamp.MusicService`), текстовый редактор с выбором кодировки.

**Сеть.** FTP, FTPS, SFTP, SMB 1–3, WebDAV(S), поиск в локальной сети (mDNS), Dropbox, Google Drive, OneDrive, Box, Яндекс Диск, pCloud, Nextcloud, ownCloud.

**Серверы.** «Доступ с ПК» (FTP/FTPS-сервер на устройстве), локальный HTTP-сервер для стриминга медиа (`127.0.0.1`).

**Системное.** Root-режим через `su --mount-master`, Shizuku, USB OTG (libaums, в том числе «сырой» USB), извлечение носителей, Android TV.

**Монетизация.** Подписка, разовая покупка, промокоды, бесплатный пробный период; реклама AdMob в шести местах (раздел 6.6).

### 3.2. Как устроен код

- **Модель «один экран — фрагмент»** внутри `MainActivity`: главная (`fragment_desktop2`), список файлов, поиск, анализ, приложения, сервер. Навигация через `DrawerLayout` с вкладками «Закладки / История / Открытые окна».
- **Асинхронность.** Собственный форк `AsyncTask` (`ax/a8/o.java`, свои `Executor` и `Handler`), от него наследуются **103 класса**. Отмена и структурная конкурентность почти не используются.
- **Списки.** `FileListView extends ListView`, `FileGridView extends GridView`, `DesktopGridView extends GridView`; 11 адаптеров на `BaseAdapter`/`ArrayAdapter`.
- **Файловая абстракция.** Хелперы под каждый тип хранилища (`file/j0` WebDAV, `file/g0` SMB, `file/a0` облака, `ax/f7/u0` root-shell и т. д.) с общим интерфейсом.
- **Root.** Постоянный процесс `su`, команды пишутся в stdin, конец ответа ищется по маркеру `END_OF_CMD`, вывод `ls -lan` разбирается построчно. Экранирование путей корректное (`'…'"'"'…'`), но разбор `ls` хрупок для имён с переводом строки.
- **Хранение настроек.** Десятки файлов `SharedPreferences` (`SFTPPrefs`, `SMBPrefs`, `USER_SETTINGS`, `KeyManager`…); Room используется точечно.
- **Удалённая конфигурация.** Firebase Remote Config задаёт рекламу: `enable_ads_after`=2 дня, `enable_ads_to_all_after`=5, `show_intensive_ads_after`=8, `show_app_open_ads`, `exit_app_ads_style` и др. (`ax/z7/d.java`).

## 4. Безопасность и приватность

Оценка: **Высокая** — реальный риск утечки учётных данных или MITM; **Средняя** — ослабление защиты при определённых условиях; **Низкая** — гигиена.

### S1. Учётные данные не защищены по-настоящему — Высокая

- `ax/f7/n1.java`: AES-GCM с ключом из PBKDF2(`PBEwithSHA256AND256BITAES-CBC-BC`) и **всего 256 итерациями**. Пароль для PBKDF2:
  - для FTP/SFTP/SMB/WebDAV это **имя хоста**, которое лежит открытым текстом в том же файле настроек (`file/j0.java`: `p(edit, i, oVar.d() /* host */, …)`);
  - для облаков это **константы в коде** (`ax/b7/a.java`): `"File Manager SFTPHelper Cipher"`, `"File Manager WebDAV Cipher"`, `"www.dropbox.com"`, `"drive.google.com"`, `"www.pcloud.com"`… Хранилище `KeyManager` только читается, никогда не записывается, поэтому всегда используются константы.
- Для старых записей есть ветка `DESede/ECB` с тем же ключом.
- При любой ошибке шифрования метод `e()` **возвращает исходную строку**, то есть пароль молча сохраняется открытым текстом.
- **Как исправить.** Ключ AES-256-GCM в **Android Keystore** (не экспортируемый, при желании `setUserAuthenticationRequired` для «защищённой папки»). Шифровать все секреты этим ключом (Tink или Keystore + DataStore). При первом запуске новой версии мигрировать старые значения. При ошибке шифрования никогда не сохранять открытый текст.

### S2. Секреты уходят в облачную резервную копию — Высокая

- `res/xml/data_extraction_rules.xml` → `<cloud-backup disableIfNoEncryptionCapabilities="false">` включает `SFTPPrefs.xml`, **`SFTPKeyPrefs.xml`**, `SMBPrefs.xml`, `FTPPrefs.xml`, `WebDAVPrefs.xml`, `DropboxPrefs.xml`, `GoogleDrivePrefs.xml`, `OneDrivePrefs.xml`, `YandexDiskPrefs.xml`, `BoxCloudPrefs.xml`, `PCloudCloudPrefs.xml`.
- Вместе с S1 это значит, что пароли, токены и приватные SSH-ключи в обратимом виде попадают в Google Drive пользователя, даже если резервная копия не зашифрована сквозным шифрованием.
- **Как исправить.** Исключить секреты из `cloud-backup` и оставить только список серверов без паролей. Либо поставить `disableIfNoEncryptionCapabilities="true"`. После S1 ключи Keystore не восстанавливаются на другом устройстве, поэтому нужен понятный сценарий повторного входа.

### S3. TLS: «доверять один раз» означает «не проверять никогда» — Высокая

- `file/j0.java` (WebDAV): при ошибке рукопожатия выполняется пробное соединение с trust-all `TrustManager`, сертификат показывается пользователю (`layout/ssl_certificate.xml`).
- `ax/oo/a.java` (HTTP-клиент WebDAV): `checkServerTrusted() { if (this.c) return; … }`. После согласия пользователя флаг `c` отключает проверку **для любого сертификата**, а не для того, который пользователь видел. Без флага проверяется только срок действия листового сертификата `checkValidity()`, цепочка доверия не проверяется.
- Аналогично `ax/lt/f.java` (FTPS): при флаге проверяется только срок действия.
- **Как исправить.** TOFU с закреплением сертификата: сохранять SHA-256 SPKI принятого сертификата, при совпадении пропускать, при несовпадении блокировать с понятным предупреждением (см. макет «Сеть», статус «Сертификат изменился — проверьте»). Без согласия использовать стандартный `X509TrustManager` платформы с полной проверкой цепочки и имени хоста.

### S4. Сетевая конфигурация слишком открыта — Средняя

- `network_security_config.xml`: `base-config cleartextTrafficPermitted="true"` и `<certificates src="user"/>` **для всех доменов**, включая API Google, Microsoft, Dropbox, Яндекса.
- Любой пользовательский CA, например из корпоративного профиля или «левого» VPN-приложения, может перехватывать трафик облаков.
- **Как исправить.** В `base-config` доверять только системным CA. Пользовательские CA и cleartext оставить для серверов, которые пользователь добавил сам, через собственный `TrustManager` из S3: Network Security Config не умеет задавать диапазоны IP, поэтому решать это нужно кодом.

### S5. Устаревшие OAuth-потоки — Средняя

- Яндекс: `https://oauth.yandex.ru/authorize?response_type=token…`. Это implicit flow, его не рекомендуют (OAuth 2.0 Security BCP, RFC 9700).
- **Как исправить.** Authorization Code + PKCE через Custom Tabs (AppAuth), refresh-токены хранить по схеме S1.
- Для Google Drive запрашивается полный scope `…/auth/drive`. Для файлового менеджера это оправдано, но его нужно прямо объяснить на экране согласия.

### S6. FTP-сервер «Доступ с ПК» — Средняя

- `FtpServerService.D()`: `bind(new InetSocketAddress(port))` слушает **все интерфейсы**, включая мобильную сеть и точку доступа.
- Есть анонимный режим; по умолчанию FTP без шифрования (FTPS опционален, сертификат самоподписанный на 10 лет).
- **Как исправить.** Слушать только IP Wi-Fi-интерфейса. Пароль по умолчанию (случайный, показывать один раз) и FTPS по умолчанию. Автоостановка по таймауту. Список подключённых клиентов с кнопкой «Отключить» (макет «Сеть»).

### S7. Лишние экспортируемые компоненты — Низкая

- `StorageCheckReceiver` экспортирован с собственным action и без разрешения, хотя вызывается только своим `PendingIntent`. Любое приложение может вызывать уведомления «память заполнена». → `exported="false"`.
- `ShortcutActivity` экспортирован (так нужно для ярлыков), но открывает любую закладку или файл по запросу любого приложения. → Подписывать ярлыки (HMAC в extra) или проверять `ShortcutManager`.
- `MyFileProvider` с `<root-path path="/"/>` и `<grant-uri-permission pathPrefix="/"/>` потенциально раздаёт любой путь. → Ограничить конкретными каталогами.

### S8. Локальный HTTP-сервер без токена — Низкая

- `HttpServerService` (`ax/u7/b` поверх NanoHTTPD-подобного `ax/cp/a`) слушает `127.0.0.1` без проверки доступа. Другое приложение на устройстве может перебрать порт и путь.
- → Случайный токен в URL и проверка UID через `Binder`, либо отдача контента через `ContentProvider`.

### S9. Приватность диагностики — Низкая

- `ShortcutActivity`: `ax.t6.d.c("shotcuturinull", new Exception("shortcut error:" + data))` отправляет в отчёт об ошибке URI с путём к файлу.
- 488 вызовов `printStackTrace()`; события аналитики содержат расширения открываемых файлов.
- → Удалять пути и имена из отчётов, использовать единый логгер с уровнями и вырезать debug-логи в release.

### Что сделано хорошо

- Проверка Zip Slip при распаковке (`ax/f7/q0.java`: `getCanonicalPath().startsWith(dest + separator)`).
- Корректное экранирование путей в root-командах.
- JSch 2.16 (форк mwiede) с современными KEX и шифрами, `StrictHostKeyChecking=ask`.
- UMP (согласие GDPR), `firebase_analytics_collection_enabled=false` до согласия.
- Локальный стриминг слушает только loopback.

## 6. Аудит дизайна и UX

### 6.1. Визуальный язык

- **Пять несвязанных палитр.** Тулбар `material_grey_900` (почти чёрный), бирюзовый акцент `#008578`, индиго в поиске (`#3F51B5`/`#303F9F`, Material 2014), голубой индикатор вкладок `#BBDEFB`, фон нижней панели из 9-patch `cab_background_bottom_holo_dark` (эпоха Holo, 2012). В разметке 52 захардкоженных цвета.
- **Тема.** `Theme.MaterialComponents` (M2) с вручную добавленными M3-ролями (`colorPrimaryContainer` и т. п.). Нет `DynamicColors`, нет поверхностей с тональной высотой.
- **Главная.** Тёмная полоса 192 dp с каруселью (память / последние / уведомления) и декоративной «волной» (`bg_wave`), под ней вкладки и сетка белых круглых значков 64 dp на 96 dp колонках. Много декора, мало полезной информации: размер занятого места и путь к очистке не видны сразу.

### 6.2. Значки

- 206 PNG только в `drawable-xhdpi` (192×192). На экранах xxhdpi/xxxhdpi, а это большинство современных телефонов, они масштабируются и **теряют резкость**.
- Смешаны три стиля: объёмные папки со стопкой листов, серые диски со светодиодом, CD-диск; плоские глифы Material (`v_shape_*`); логотипы сервисов в фирменных цветах. Отдельно стоит объёмная корзина с градиентом.
- Оранжево-жёлтая папка (`shape_folder #EBC849`) не связана с бирюзовым акцентом бренда.

### 6.3. Навигация и информационная архитектура

- Основные разделы спрятаны в выдвижном меню; «Открытые окна» (вкладки) найти сложно, это отдельный оверлей.
- Строка пути: кнопки 44 dp (меньше рекомендованных 48), разделители «›» мелкие, текущая папка выделена только цветом текста.
- Нижнее контекстное меню собрано из `LinearLayout` с текстом 14 **dp**, поэтому оно не масштабируется настройкой размера шрифта.

### 6.4. Доступность (a11y)

- `supportsRtl="false"`, хотя есть арабская локализация. В разметке 138 `marginLeft` против 35 `marginStart` и 83 `paddingLeft` против 14 `paddingStart`.
- 11 `ImageButton` без `contentDescription`; 7 размеров текста в `dp`.
- Сортировка обозначается символами «▲▼» прямо в тексте («Имя ▲»), и TalkBack читает их как «чёрный треугольник».
- Состояние «выбран» в списке показано в основном цветом фона.

### 6.5. Тёмная тема

- Настройка темы скрыта, пока нет Premium (`ax/g7/p1.java`: `if (!ax.z7.h.g()) listPreference.N0(false)` — пункт «Тема» скрывается без Premium).
- Значение по умолчанию `1` (`MODE_NIGHT_NO`), поэтому системная тёмная тема игнорируется. Ночью приложение слепит, на OLED тратит заряд, а для людей со светобоязнью это проблема доступности.

### 6.6. Реклама и монетизация

- Форматы: баннер внизу главной, нативная реклама на главной, в корзине, в анализе памяти, в видеоплеере, при выходе (`dialog_exit_ads`), **App Open** (`ads/AppOpenManager`), видео за награду («уберите рекламу на день»).
- В Remote Config есть флаг `desktop_ads_prevent_surprise`: видимо, разработчики сами знают о проблеме случайных нажатий.
- Окно оценки: «Если вам нравится эта программа, пожалуйста, поставьте нам 5 звёзд» с кнопкой «Поставить 5★». Рекомендации Google Play по запросу отзывов прямо советуют не просить конкретную оценку («поставьте 5 звёзд»), а In-App Review API не используется.
- Premium продаёт базовые вещи (тёмную тему), из-за чего покупка воспринимается как выкуп у рекламы, а не как получение ценности.

### 8.1. Принципы

1. **Спокойная база, один акцент.** Нейтральные поверхности с лёгким бирюзовым оттенком; цвет `primary` только у главного действия.
2. **Цвет обозначает смысл.** Тональные пары (контейнер / на контейнере) по типам файлов и цвета состояний. Цвет всегда дополнен значком и подписью.
3. **Удобно пальцем.** Касание ≥ 48 dp, действия над выбранным внизу, FAB справа внизу, строки 64 dp.
4. **Честно.** Тёмная тема и Material You бесплатны, реклама не мешает работе, перед списанием денег — напоминание.

### 8.2. Токены (полностью в `design/tokens.json` и `design/android/`)

| Роль | Светлая | Тёмная |
|---|---|---|
| primary | `#006A64` | `#7FD6CD` |
| primaryContainer | `#9DF2E9` | `#00504B` |
| secondaryContainer | `#CCE8E4` | `#324B48` |
| surface | `#F5F9F8` | `#0E1514` |
| surfaceContainer | `#E9EFEE` | `#1A2120` |
| onSurface | `#161D1C` | `#DDE4E2` |
| onSurfaceVariant | `#3F4948` | `#BEC9C7` |
| error | `#BA1A1A` | `#FFB4AB` |

Контраст проверен по WCAG 2.2: все пары «текст / фон» в токенах и макетах не ниже 6:1 (обычный текст на `surface` 8,8:1 в светлой и 10,9:1 в тёмной теме, тексты категорий на своих плитках 6,9–8,1:1), рамки `outline` не ниже 4,2:1.

Основной цвет `#006A64` — затемнённая версия нынешнего `#008578`, поэтому бренд узнаётся, а контраст белого текста на нём выше 6:1. Шрифты: **Roboto Flex** для интерфейса (вариативный, кириллица, оптический размер) и **Roboto Mono** для путей, адресов, хэшей и отпечатков.

### 8.3. Как внедрять

- Новые экраны делать в Compose, на `MaterialTheme(colorScheme = if (dynamic) dynamicColorScheme(ctx) else brandScheme)`; токены из `design/android/values*/colors.xml` подходят и для XML-экранов.
- Для XML-экранов сменить родительскую тему на `Theme.Material3.DayNight.NoActionBar` (пример в `design/android/values/themes.xml`) и включить `DynamicColors.applyToActivitiesIfAvailable(app)`, если пользователь включил «Цвета из обоев».
- Значки собрать в один `ImageVector`-набор или в `VectorDrawable` с `android:tint="?attr/colorOnSurfaceVariant"`; растровые `icon_*` удалить.
